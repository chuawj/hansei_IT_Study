# 웹 개발 제안서  
## I. 제안개요  

### (1) 제안의 목적과 배경  
- 실제 한세대학교 수강신청 시스템은 사전 연습이 불가능하며, 실수 시 학생 본인에게 불이익이 발생할 수 있음.  
- 학생들이 사전에 충분히 연습하여 실전에서 당황하지 않고 원하는 과목을 원활히 신청할 수 있도록, 실제 시스템과 유사한 **웹 기반 모의 수강신청 사이트**를 제작.  

### (2) 제안 시스템의 개요  
- 한세대학교 수강신청 시스템을 모방한 **연습용 웹사이트** 제공.  
- UI/UX를 실제와 유사하게 구현하여, 누구나 자유롭게 수강신청 과정을 체험 가능.  
- 모든 데이터는 **브라우저 localStorage**에 저장되며, 서버와의 연동은 없음.  

### (3) 기대효과  
- 학생들이 수강신청 과정을 사전에 충분히 연습 가능.  
- 실전에서의 실수를 줄이고, 원하는 과목을 더 쉽게 신청할 수 있음.  
- 실제 시스템과 유사한 환경에서 UI/UX를 익혀 **사용자 경험 향상**.

## II. 개발자 소개  

### (1) 개발자 정보  
- 이름: 최현준  
- 소속: 한세대학교 재학 중  
- 전공: it학부
- 개발 목적: 실제 수강신청 시스템을 연습할 수 있는 환경을 제공하기 위해 개인적으로 개발  

### (2) 프로젝트 성격  
- 개인 개발 프로젝트  
- 실제 수강신청 시스템의 UI/UX를 모방한 웹 기반 연습 플랫폼  
- 학습 및 실전 대비를 위한 실용적 목적  

### (3) 개발 동기  
- 한세대학교의 수강신청 시스템은 실전 외에는 접근이 불가능하고, 연습 기회가 없어 실수 시 불이익을 감수해야 하는 구조입니다.  
- 저 역시 수강신청 과정에서 긴장하거나 실수한 경험이 있었고, 이를 계기로 **누구나 자유롭게 연습할 수 있는 환경**이 필요하다고 느꼈습니다.  
- 이 프로젝트는 단순한 모의 시스템을 넘어서, **후배들이 실전에 앞서 자신감을 갖고 준비할 수 있도록 돕는 도구**가 되기를 바랍니다.  
- 개발 과정에서 UI/UX, 데이터 구조, 사용자 흐름 등을 직접 설계하며 개발 실력도 키울 수 있었고, 같은 고민을 가진 학생들에게 실질적인 도움이 되기를 기대합니다.

## III. 기술부분  
[기술 명세서 보러 가기](기술명세서.md)
### (1) 기획부분  
- 주요 기능:  
  - 교과목 조회 (학부/학과/이수구분/과목명 검색)  
  - 예비수강신청(장바구니)  
  - 실제 수강신청  
  - 수강내역 조회  
  - 수강신청 오픈 타이머  
  - 대기열(Queue) 기능  

- 추가 예정 기능:  
  - 학교 공식 디자인과 유사한 UI 개선  
  - 실제 수강 데이터 반영  

### (2) 인터페이스 디자인부분  
- 실제 수강신청 사이트와 유사한 UI/UX 제공  
- 반응형 UI (데스크탑 기준, 모바일 대응 선택적)  
- 주요 화면:  
  - **index.html**: 메인, 타이머, 대기열 토글, 탭 메뉴  
  - **register.html**: 수강신청 화면 (검색, 빠른 신청, 내역, 대기열 모달)  
  - **basket.html**: 예비수강신청 화면 (검색, 장바구니 관리)  

### (3) 시스템 / 프로그램부분  
![ERD 다이어그램](한세_수강신청%20연습_erd.png/)
- **데이터 구조**  
  - `subjects`: 과목 마스터 데이터 (code, name, dept, major, year, type, credit, cap, prof)  
  - `categoryData`: 학부/학과/전공 데이터  
  - `localStorage`: basketList, registerList, queueEnabled, registerQueueRequired  

- **주요 JS 모듈**  
  - `data.js`: 과목/카테고리 데이터  
  - `register.js`: 수강신청 로직, 대기열, 신청/삭제 처리  
  - `basket.js`: 예비수강신청 로직  
  - `queue_modal.js`: 대기열 모달 제어  
  - `queue_toggle.js`: 대기열 ON/OFF 관리  
  - `index.js`: 탭 전환, 타이머, iframe 제어  

- **데이터 흐름**  
  - 모든 신청/삭제/토글은 localStorage에 즉시 반영  
  - storage 이벤트를 활용해 iframe 간 실시간 동기화

## V. 제약사항 및 주의사항

- 모든 데이터는 브라우저의 `localStorage` 에 저장됩니다. 서버와의 연동이 없으므로 브라우저/기기 간 데이터 동기화는 지원하지 않습니다.
- 로그인/계정 기능이 없습니다. 동일 브라우저에서는 누구나 데이터를 변경할 수 있으므로 실사용 데이터와 혼동하지 마세요.
- 동시다발적 실제 사용자 트래픽을 시뮬레이션하지 않습니다. 대규모 동시접속/경쟁 상황에서의 정확한 동작을 보장하지 않습니다.
- localStorage 초기화(브라우저 캐시 정리 등)는 데모 데이터의 영구 삭제를 초래할 수 있으며 복구가 불가능합니다.
